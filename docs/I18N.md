# English source catalog and Japanese translations

The plugin uses English source strings with the `atshift-members` text domain. WordPress loads Japanese translations for locale `ja` from the bundled MO file. English uses the source text; an `en_US` PO/MO pair is also included for distribution and translation tooling.

## Files

- `languages/atshift-members.pot`: English source catalog.
- `languages/atshift-members-ja.po`: editable Japanese translations.
- `languages/atshift-members-ja.mo`: compiled Japanese translations loaded by WordPress.
- `languages/atshift-members-en_US.po` and `.mo`: explicit English catalog.
- `languages/atshift-members-{locale}-{hash}.json`: WordPress JavaScript catalogs for `assets/media.js`.

The media script depends on `wp-i18n` and uses `wp_set_script_translations`. The filename hash is derived from the plugin-relative script path, as required by WordPress.

## Updating

Edit English gettext messages in PHP/JavaScript, then add matching Japanese entries to the Japanese PO file. Run:

```sh
python3 tools/build-languages.py --php /path/to/php
```

PHP and GNU gettext (`msgfmt`) are required. The builder rejects missing Japanese translations and mismatched printf or email placeholders. It regenerates POT, PO, MO, and script JSON files with source references. `msgfmt --check --check-format` runs for both locales. Catalog header dates currently identify this 2026-09-11 translation revision; update them in the builder for a future translation revision.

Build the installable plugin with:

```sh
python3 tools/build-package.py /tmp/atshift-members.zip
```

The package includes all language catalogs but excludes development tools and tests.

## Behavior and boundaries

- Admin, front-end, default email, and media-picker text are translatable.
- Full messages use placeholders where names, paths, or counts need a language-specific order.
- Saved email templates, signatures, custom field labels, existing page titles, and user content are not rewritten by a language change. Only unsaved defaults follow the current WordPress locale.
- Default outgoing email text follows the locale of the sending request/worker. This change does not add a per-recipient language preference.
- Text supplied by integrated plugins remains the responsibility of each provider's language catalog.
- `Registration::accepted_message()` returns the localized generic request response. The legacy `Registration::ACCEPTED` constant contains the English source and should not be used for display or localized assertions.

## Verification

The local QA suite (not included in this repository) was run against a disposable WordPress fixture to verify English → Japanese → English loading, admin and account forms, default emails, plugin badges, WordPress script-catalog resolution, unchanged form identifiers, and preservation of saved settings/templates.
