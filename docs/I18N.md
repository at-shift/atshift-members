# Translation catalogs

atshift Members uses English source strings with the `atshift-members` text
domain. Bundled catalogs are maintained for these WordPress locales:

- Japanese (`ja`) and US English (`en_US`)
- German, Spanish, French, Indonesian, Italian, Korean, Dutch, Polish,
  Brazilian Portuguese, Russian, and Turkish
- Simplified Chinese and Traditional Chinese

Japanese-first legacy labels pass their English catalog key through
`Dashboard::label()`. This preserves the reviewed Japanese wording while every
other locale follows the normal WordPress translation lookup.

## Files

- `languages/atshift-members.pot`: English source catalog.
- `languages/atshift-members-{locale}.po`: editable translation catalog.
- `languages/atshift-members-{locale}.mo`: compiled PHP catalog.
- `languages/atshift-members-{locale}-{hash}.json`: WordPress JavaScript
  catalog for `assets/media.js`.

The media script depends on `wp-i18n` and uses
`wp_set_script_translations()`. The JSON filename hash is derived from the
plugin-relative script path, as required by WordPress.

## Updating

Edit the English gettext message in PHP or JavaScript and update every affected
PO entry. When adding a `Dashboard::label()` pair, keep the exact reviewed
Japanese copy in the first argument and the English source key in the second.
Then run:

```sh
python3 tools/build-languages.py --php /path/to/php
```

PHP and GNU gettext (`msgfmt`) are required. The builder does not contact a
translation service. It rejects missing locale
entries and translations that alter printf placeholders, email placeholders,
HTML, shortcodes, entities, or URLs. It regenerates the POT, all PO/MO files,
and all script JSON files with source references. `msgfmt --check
--check-format` runs for every locale.

Build the installable plugin with:

```sh
python3 tools/build-package.py /tmp/atshift-members.zip
```

The package includes the language catalogs but excludes development tools and
tests.

## Behavior and boundaries

- Admin, front-end, default email, dashboard, and media-picker text are
  translatable.
- Full messages use placeholders where names, paths, or counts need a
  language-specific order.
- Saved email templates, signatures, custom field labels, existing page
  titles, and user content are not rewritten by a language change. Only
  unsaved defaults follow the current WordPress locale.
- Default outgoing email text follows the locale of the sending request or
  worker. There is no per-recipient language preference.
- Text supplied by an integrated plugin remains the responsibility of that
  plugin's language catalog.
- `Registration::accepted_message()` returns the localized generic request
  response. The legacy `Registration::ACCEPTED` constant contains the English
  source and must not be used for display or localized assertions.

## Verification

For each catalog, run `msgfmt --check --check-format` and compare it with the
POT using `msgcmp`. The WordPress integration test loads every bundled locale,
renders PHP and JavaScript UI, checks preserved form
identifiers and placeholders, and confirms that saved settings and templates
remain unchanged.

## Translation review workflow

No Google Translate integration is used. Catalogs are edited locally; the
builder only extracts messages, validates them, and compiles language files.
Review draft translations in their actual UI context before accepting them.
In particular, distinguish post approval from time expressions, returning a
request for revision from cancelling it, email delivery from physical shipping,
and leaving a membership from an inactive personality or a bank withdrawal.

Keep product names and copyable configuration keys unchanged. The builder
checks those literals as well as technical placeholders and rejects unresolved
translation markers. A translation may correctly match English (for example,
French “Public”); matching the source alone is not an error.

Keep form markup, option values, HTML attributes, and submission identifiers
outside translated messages. Translate visible text and accessibility labels
separately, escaping each at its output context. This prevents a translation
from changing a form's structure or stored values. Preserve reviewed Japanese
source pairs when splitting a legacy HTML-containing message.

Automated catalog completeness and syntax checks do not establish naturalness
or semantic correctness. The 2026-09-27 review corrected the principal UI terms,
account states, notification preferences, approval scope, and handoff messages;
it was not a native-speaker certification of every sentence.
